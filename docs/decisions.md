# Design decisions

Decisions made while implementing [the architecture](architecture.md), with
their reasons. Numbers are stable; superseded decisions say so.

| # | Decision | Reason |
|---|---|---|
| D1 | Own WARC package (`internal/warcio`) and recording transport (`internal/recorder`) instead of an external WARC library. | Full control over raw bytes, `revisit`/`metadata`/`resource` records and coordinator-driven deduplication; fewer dependencies. The transport uses one connection per request, HTTP/1.1 and no transparent decompression. |
| D2 | Deduplication only hits records already committed to the index, plus a local map within one capture. | A revisit never points to a missing record. A race produces two full copies, which is acceptable. |
| D3 | Page text, title, publication date, source and structured data are written to a `metadata` record (JSON) of every capture. | The index, including full-text search and the open week, can be fully rebuilt from storage. |
| D4 | CDXJ lines carry the standard fields (`url`, `mime`, `status`, `digest`, `length`, `offset`, `filename`) and extra ones (`rid`, `type`, `refersTo`). | A sealed week is reindexed without scanning WARC files; other tools ignore the extra fields. |
| D5 | The `chrome` engine uses go-rod with request interception over the DevTools protocol; intercepted requests are fetched by the recorder's client. | Same effect as a MITM proxy (all traffic goes through the recorder) without managing a CA. The layer stays replaceable. |
| D6 | S3 contract tests run against an in-process fake (`gofakes3`) always, and against a real server when `HOARFROST_TEST_S3` is set. | `go test ./...` works without Docker; CI checks a real S3 server. |
| D7 | ReplayWeb.page is loaded from a CDN (its service worker via `importScripts`), not embedded in the binary. Every other web asset is bundled. | ReplayWeb.page is AGPL-3.0; the rest of the project is Apache-2.0. |
| D8 | WARC files stay `.warc.gz` with one gzip member per record; `.warc.zst` is out of scope until measured. | Universal tool support today. |
| D9 | Uploaded WACZ files are rewritten into a new WARC file with `Cookie`, `Authorization` and `Set-Cookie` removed and digests recomputed. | No secrets in the archive; deduplication works for uploads too. |
| D10 | `WARC-Payload-Digest` is computed over the raw bytes after the HTTP headers, also for `chunked` responses. | The `warcio`/Heritrix convention; `warcio check` passes. |
| D11 | The `metadata` record of each page has its location in the page index, and `pages.jsonl` has `metaOffset`/`metaLength`. | Text, DOM snapshot and capture details are read with one range request, also after reindexing. |
| D12 | The `chrome` engine also stores the rendered DOM as a `resource` record (`urn:dom:<url>`). | Fast preview of pages rendered by JavaScript. |
| D13 | OCR results are stored as a new `metadata` record (`kind: ocr`), not only in the database. | The index stays rebuildable. |
| D14 | Legacy imports go to the week of the file date (or the current week when that one is sealed) as `resource` records. | Search covers everything; the index stays rebuildable. |
| D15 | Conditional requests (`If-None-Match`) are not sent; a 304 response would be stored as a `server-not-modified` revisit. | Optional in the design; sending them would require workers to read the archive. |
| D16 | Development and CI use SeaweedFS as the real S3 server (public MinIO images are no longer available). | Any S3-compatible backend works. |
| D17 | Conformance is checked with independent tools (`conformance/`, `HOARFROST_CONFORMANCE=required` in CI). SURT keys match the Python `surt` library (differential test on thousands of URLs). `metadata` records use `WARC-Target-URI: urn:pageinfo:<url>` (the Browsertrix convention), because pywb served them instead of the page. | The archive must work with ordinary WARC tools. |
| D18 | Block lists (Pi-hole/adblock: hosts files, domain lists, `\|\|domain^` rules, `@@` exceptions) are refreshed by the coordinator (ETag, cache, protection against empty lists) and passed to workers through a version in the lease; StevenBlack's list by default; the host of the archived page is never blocked; the list version is recorded in `warcinfo`. | Ads and trackers are not worth archiving. |
| D19 | Several storages (`HOARFROST_STORAGES`), chosen per source or per URL/upload; each storage is an independent archive; deduplication and the seen-URL filter are per storage; one shared index with a `storage` column; a worker only takes jobs for storages it has. | Captures can be sorted into separate buckets or directories. |
| D20 | Capture configuration (sources, defaults, block lists) and the poll state of every source live in the database and are managed in the UI and through `/api/sources`; there is no `sources.yaml`. A copy of every change is still written to `config/sources/*.yaml` in storage. | Nobody edits YAML by hand; the schedule survives restarts; the archive still documents how it was collected. |
| D21 | PostgreSQL replaces SQLite: schema `app` (migrations in `internal/appdb`) and schema `archive_index` (versioned, dropped and rebuilt from storage on a version change). Full-text search uses `tsvector` with the `simple` configuration and diacritics folded in Go. Leases use `FOR UPDATE SKIP LOCKED`. `hoarfrost import-sqlite` moves old application data. | Concurrent access, faster search and statistics at millions of records. |
| D22 | A CDXJ file is written next to every WARC file in `incoming/`; missing ones for open weeks are added in the background on start. | The open week is readable with standard tools (pywb) before it is sealed. |
| D23 | Sealing also writes `weekly/<year>/W<week>.parquet`: one row per capture sorted by URL and time, with title, description and schema.org data (zstd, row groups of 10,000, bloom filter on URL); its hash is in the catalog and checked by `verify`. | Analysis of a week with DuckDB, pandas or Spark without reading WARC files. |
| D24 | Description, authors and schema.org objects (JSON-LD including `@graph`, microdata, RDFa Lite; limited to 32 objects / 64 KiB) are extracted at capture time and stored in the `metadata` record and the index. | Other applications get structured article data without parsing HTML. |
| D25 | Applications read the archive with read-only API keys (`hfr_…`) managed by admins; changing the archive needs a user token (`hf_…`) with the editor role. Pages are identified by `captureId` (the UUID of the `metadata` record), which survives reindexing, unlike the numeric page id. The read API is described in `docs/openapi.yaml`, served at `/api/openapi.yaml` and checked against the routes by a test. | hoarfrost collects and stores; presentation and analysis belong to other applications. |
| D26 | Statistics shown on the Dashboard come from counters (`epoch_stats`) maintained when captures are indexed, not from scans of `records`. | Pages load in well under a second with millions of records. |
| D27 | Open Graph and Twitter Card properties and microformats2 items (parsed with `willnorris.com/go/microformats`, MIT) are extracted at capture time next to schema.org data, together with keywords from all of them and `<meta name="keywords">`; they are stored in the `metadata` record, so `pages.jsonl` and a rebuilt index have them. Embedded HTML of `e-*` properties is dropped and values are shortened, since the page itself is archived. | Tags, images, types and authors make content findable and are what other applications analyse. |
| D28 | In the index, structured data is kept twice: whole JSON per page in `pages` (one read for the API) and flattened into `page_items` (every schema.org object and mf2 item, nested ones with `parent_id`), `page_properties` (one row per Open Graph value) and `page_keywords` (folded key for filtering). | Questions across pages (all `Person` objects, every `og:type`, pages tagged X) are plain SQL instead of JSON traversal; the index is derived, so the duplication costs only space. |
